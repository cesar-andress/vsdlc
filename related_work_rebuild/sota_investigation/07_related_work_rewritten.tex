\section{Related Work}
\label{sec:related-work}

GitHub search makes it easy to retrieve repositories that contain files instructing coding agents how to work in a project~\cite{agentsmd2025,cursor2024docs,brown2024copilot,claude2024docs,anthropic2024mcp}.
A path match is a retrieval event, not a membership proof for the analytic population named in a research question~\cite{kalliamvakou2015indepth,baltes2022sampling}.
Repositories that satisfy an instruction-file predicate may still be off-target for a study that claims to analyze conventional applications---including, in principle, documentation hosts, prompt packs, coursework templates, or AI-builder tooling---so unvalidated denominators can bias downstream statistics~\cite{kalliamvakou2015indepth,baltes2022sampling}.
This section situates that risk in prior work and delimits what remains open.
We do not claim that sample--target mismatch on GitHub is newly discovered; that lesson is established~\cite{kalliamvakou2015indepth,baltes2022sampling,howison2004perils}.
The open question is narrower: whether discovery frames built from AI-instruction artifacts require an operational audit in which contamination is target-conditional, structured by predicate family, and sensitive to the consensus protocol used to aggregate coder labels.
Answering that question matters because the predicates themselves are now concrete and searchable~\cite{agentsmd2025,cursor2024docs,brown2024copilot,claude2024docs,anthropic2024mcp}, while peer-reviewed methodological guidance on sampling frames~\cite{baltes2022sampling} and surveys of prompt-enabled and LLM-for-SE systems~\cite{chen2025promptware,hou2024llm4se} do not, to our reading, specify how to audit membership under those predicates.

\subsection{Mining software repositories methodology}
\label{subsec:rw-msr}

Mining software repositories (MSR) was articulated as a research programme concerned with recovering process and product knowledge from archival development data~\cite{hassan2008road}.
The programme's early agenda already mixed opportunity with methodological risk: repositories are convenient observational instruments, but convenience does not guarantee that recovered units match the constructs named in a research question~\cite{hassan2008road,wohlin2012}.
Subsequent infrastructure made GitHub-scale extraction routine.
Event streams and mirrors lowered the cost of assembling candidate sets~\cite{gousios2013,gousios2014lean}; commit-level tooling reduced the engineering burden of traversing histories~\cite{spadini2018pydriller}; and cross-forge corpora expanded coverage beyond a single forge's search API~\cite{ma2019woc,pietri2019swh,dicossmo2017softwareheritage}.
A systematic mapping of GitHub-based software engineering research catalogues the topical breadth that such pipelines enable~\cite{cosentino2017mapping}.

This line largely reduces \emph{access} and \emph{extraction cost}.
It does not, by itself, establish that repositories retrieved by a filename or path predicate belong in the population a study claims to represent~\cite{kalliamvakou2015indepth,baltes2022sampling}.
When discovery is cheap, the binding constraint shifts from ``can we find repositories?'' to ``do the repositories we found match the target?''---a validity question that retrieval completeness cannot answer~\cite{baltes2022sampling,wohlin2012}.
MSR methodology therefore supplies the backdrop for the present article, but not the audit of instruction-artifact discovery frames.

\subsection{Repository discovery and GitHub sampling}
\label{subsec:rw-discovery}

GitHub sampling practice has been studied both descriptively and critically.
Dabic et al.\ examine how MSR studies sample projects and how sampling choices shape corpora~\cite{dabic2021sampling}.
Baltes and Ralph review sampling across software engineering research and argue that frames, populations, and generalization claims must be stated explicitly if empirical results are to be interpretable~\cite{baltes2022sampling}.
Stars, social signals, and related metadata are fragile popularity and contribution proxies~\cite{borges2016popularity,tsay2014influence}, so ranking or filtering by metadata alone does not settle membership.
Software Heritage and World of Code further show that discovery can be redesigned for archive-scale coverage and provenance~\cite{ma2019woc,pietri2019swh,dicossmo2017softwareheritage}.
Larger coverage does not remove the need to define and defend the analytic population relative to the research question~\cite{baltes2022sampling}.

A related curation literature filters GitHub for engineered software projects.
RepoReapers classifies engineered versus non-engineered repositories~\cite{munaiah2017curating}; PHANTOM revisits curation with time-series clustering~\cite{phantom2020}.
These filters remove substantial non-software noise and are often the right first screen for MSR studies that intend to analyze software development activity~\cite{munaiah2017curating,phantom2020,kalliamvakou2015indepth}.
They do not equate engineered status with membership in a study-specific analytic population~\cite{baltes2022sampling,wohlin2012}.
In particular, an engineered repository can still be the wrong \emph{product role} for a conventional-application question (for example, tooling or template hosts), just as the same repository may be on-target for an AI-tooling question.
Whether such off-target-but-engineered cases arise under instruction-file predicates is an empirical residual relative to RepoReapers and PHANTOM, not a result those filters already report~\cite{munaiah2017curating,phantom2020}.
Prevalence is therefore target-conditional: the membership question cannot be collapsed into a universal ``is engineered?'' classifier~\cite{baltes2022sampling,wohlin2012}.

Discovery infrastructure and sampling guidelines leave an operational remainder.
They tell researchers to declare a frame and to avoid obvious toys~\cite{dabic2021sampling,baltes2022sampling}; they do not specify how to audit frames whose inclusion event is ``contains instruction file~$X$,'' nor whether contamination should be reported by predicate family when predicates are heterogeneous~\cite{baltes2022sampling,chen2025promptware}.
Whether a single frame-wide contamination percentage is interpretable under such heterogeneity is therefore open for instruction-artifact frames rather than settled by prior sampling guidance~\cite{dabic2021sampling,baltes2022sampling}.

\subsection{Construct validity and sampling bias}
\label{subsec:rw-validity}

Forge mining warnings long predate GitHub: SourceForge status and metadata systematically mislead naive samples~\cite{howison2004perils}.
On GitHub, Kalliamvakou et al.\ show that many entities are not software projects, that activity proxies are unreliable, and that pipelines inherit those mismatches~\cite{kalliamvakou2015indepth}.
Classical experimental guidance treats operational definitions and constructs as first-class validity objects~\cite{wohlin2012,runeson2009}.
Siegmund et al.\ document community disagreement about the relative priority of internal and external validity~\cite{siegmund2015views}, which makes undeclared analytic targets especially risky when authors later generalize from a retrieved sample.
Ampatzoglou et al.\ taxonomize threats to validity in secondary studies~\cite{ampatzoglou2019threats}; Verdecchia et al.\ critically reflect on how threats are discussed in software engineering research more broadly and urge stronger alignment between claimed constructs and measured ones~\cite{verdecchia2023threats}.
Construct failures also appear in change-based mining when tangled commits break the intended link between commits and defects~\cite{herzig2013tangled}.

Two implications follow for instruction-artifact frames.
First, the peril is not only that GitHub contains non-projects; path-based retrieval can also admit software entities that fail a study-specific membership definition even when they are recognizably software~\cite{kalliamvakou2015indepth,baltes2022sampling}.
Engineered-project filters address a related but distinct screen and therefore do not, by themselves, discharge that membership obligation~\cite{munaiah2017curating,phantom2020}.
Second, validity reporting that lists generic threats without naming the analytic target, the discovery predicates, and the label-aggregation rule leaves the estimand under-specified~\cite{verdecchia2023threats,siegmund2015views,baltes2022sampling}.
Sampling bias research therefore motivates an audit of AI-instruction discovery without already providing one.
The contribution boundary we adopt is operational rather than taxonomic: not ``can GitHub samples be wrong?''~\cite{kalliamvakou2015indepth}, but how to measure and report wrongness when discovery is an instruction-file predicate and labels are aggregated under alternative consensus rules.

\subsection{Dataset contamination and adjacent senses of error}
\label{subsec:rw-contamination}

``Contamination'' is overloaded in adjacent literatures, and the senses must be kept distinct if citations are to remain honest.
In data mining, Kaufman et al.\ formalize train/test leakage~\cite{kaufman2012}; Moreno-Torres et al.\ unify dataset-shift phenomena~\cite{moreno2012}; Kapoor and Narayanan document leakage-driven reproducibility failures across machine-learning science~\cite{kapoor2023leakage}.
On GitHub code corpora, D{\'e}j{\`a}Vu maps massive duplication~\cite{lopes2017dejavu}, and Allamanis shows that duplication inflates learned evaluations~\cite{allamanis2019duplication}.
Cross-project defect prediction classic results show that domain mismatch collapses predictive performance even when retrieval succeeds~\cite{zimmermann2008}.

A parallel validation line studies corrupted or process-fragile labels inside otherwise scoped datasets: NASA defect data quality~\cite{shepperd2013nasa}, researcher and process bias in defect prediction~\cite{shepperd2014bias}, and SZZ and feature-collection failures under manual validation~\cite{herbold2022szz}.
Benchmark construction likewise insists on explicit scope and careful filtering~\cite{dambros2012defectbenchmark,tantithamthavorn2017validation}.
Tantithamthavorn et al.\ further show that the choice of model-validation technique can change conclusions even when the underlying defect data are held fixed~\cite{tantithamthavorn2017validation}.

These results strengthen the methodological intuition that unvalidated constructs and brittle operationalizations bias downstream claims~\cite{herbold2022szz,shepperd2013nasa,zimmermann2008}.
They do not solve path-search population mismatch for instruction-artifact frames.
Leakage and duplication pollute training or evaluation sets; sample--target contamination admits the wrong repositories into the analytic population even when no model is trained~\cite{kalliamvakou2015indepth,baltes2022sampling}.
Equating the two senses would both mis-cite prior work and obscure the estimand of this article.
We therefore reuse the validation ethos of dataset papers while keeping the contamination construct distinct~\cite{herbold2022szz,dambros2012defectbenchmark}.
For instruction-artifact frames, the open risk is membership error in the study denominator---on-target applications mixed with off-target hosts that still satisfy the path predicate---which is not the same failure mode as duplicated training snippets~\cite{kalliamvakou2015indepth,baltes2022sampling,lopes2017dejavu}.

\subsection{Reporting guidelines and reproducibility}
\label{subsec:rw-reporting}

Empirical software engineering has accumulated reporting and replication norms: case-study guidelines~\cite{runeson2009}, controlled-experiment reporting~\cite{jedlitschka2005reporting}, systematic mapping updates~\cite{petersen2015mapping}, and community empirical standards announcements~\cite{ralph2021standards}.
Those instruments improve comparability when authors disclose design choices that determine the estimand~\cite{jedlitschka2005reporting,runeson2009,ralph2021standards}.
Replication mapping and artifact studies document uneven replayability and scarce software artifacts~\cite{silva2012replication,heumuller2020,winter2022artifacts,liu2024researchartifacts}.
Repository-based studies are particularly hard to reproduce when retrieval, filters, and labels are underspecified~\cite{gonzalez2011repro,gonzalez2023revisit}.
Gonz{\'a}lez-Barahona and Robles revisit that reproducibility problem a decade later and find that many barriers persist~\cite{gonzalez2023revisit}.

These norms justify releasing worksheets, frozen labels, and alternative-protocol scripts as research products~\cite{heumuller2020,winter2022artifacts,liu2024researchartifacts}.
They do not, however, supply evidence that---in instruction-artifact frames---consensus protocols or predicate families change what a contamination rate means; that consequentiality is an empirical question for the present audit, motivated by sampling-frame critique and by sensitivity results in other SE estimands~\cite{baltes2022sampling,tantithamthavorn2017validation}.
Reporting guidance without such a hinge remains generic relative to Baltes and Ralph's sampling critique~\cite{baltes2022sampling}.
Likewise, a replication package alone is necessary hygiene rather than a scientific claim~\cite{heumuller2020,gonzalez2023revisit}.

\subsection{Human annotation and consensus protocols}
\label{subsec:rw-annotation}

Chance-corrected agreement coefficients and interpretation benchmarks remain the reporting baseline for categorical coding~\cite{cohen1960kappa,landis1977kappa}.
Multi-coder protocols and triangulation are standard in empirical software engineering case research~\cite{runeson2009}.
Golzadeh et al.\ illustrate how membership ground truth for a GitHub entity class---bots---can be constructed with careful labeling and validation~\cite{golzadeh2021bots}.
Herbold et al.\ show that manual validation can expose systematic failure in automated labeling pipelines~\cite{herbold2022szz}.
Dataset-quality work more generally treats human inspection as a corrective for process-induced error~\cite{shepperd2013nasa,shepperd2014bias}.

What is solved is the availability of agreement tools and the expectation of multi-coder discipline~\cite{cohen1960kappa,landis1977kappa,runeson2009}.
What is less settled for prevalence-style membership rates is whether the \emph{consensus rule} used to aggregate coder labels should be treated as part of the estimand rather than as an invisible implementation detail.
Sensitivity analyses elsewhere in software engineering show that methodological choices can change conclusions even when the underlying observations are fixed~\cite{tantithamthavorn2017validation}.
Transferred to membership labeling, that analogy suggests that a contamination rate reported under one tie-breaking or majority rule should not be assumed protocol-invariant without evidence~\cite{tantithamthavorn2017validation,baltes2022sampling}.
Prior work supplies measurement instruments and cousin examples of membership ground truth~\cite{golzadeh2021bots,herbold2022szz}; to our knowledge it does not report complementary consensus estimates of instruction-frame contamination on the same repositories, nor locate disagreement at membership boundaries versus product-role classes for that discovery regime.

\subsection{LLM-assisted annotation}
\label{subsec:rw-llm-annotation}

Large language models have been evaluated as annotators and judges.
Gilardi et al.\ report that ChatGPT can outperform crowd workers on some text-annotation tasks~\cite{gilardi2023chatgpt}.
Zheng et al.\ evaluate LLM-as-a-judge reliability on multi-turn benchmarks~\cite{zheng2023judge}.
In software engineering, Ahmed et al.\ ask whether LLMs can replace manual annotation of SE artifacts and give a more cautious, domain-specific answer~\cite{ahmed2025llms}.
Human--AI interaction guidelines caution against unsupervised automation of consequential judgments~\cite{amershi2019humanai}.
Preliminary requirements-engineering uses of ChatGPT illustrate both opportunity and the need for human oversight~\cite{fantechi2023}.

The evidence is conflicting across domains.
Optimistic general-NLP results therefore cannot be assumed to transfer to repository membership decisions, where GitHub metadata are sparse and product roles can be ambiguous~\cite{ahmed2025llms,kalliamvakou2015indepth,borges2016popularity}.
For the problem addressed here, LLM assistance is at best an optional adjudication aid under audit; it is not a substitute for a human-coded membership protocol whose sensitivity to consensus rules can be inspected~\cite{ahmed2025llms,runeson2009}.
Treating LLM labels as authoritative membership would import unsettled transfer assumptions into the contamination estimand~\cite{ahmed2025llms,gilardi2023chatgpt}.

\subsection{AI instruction artifacts}
\label{subsec:rw-instruction-artifacts}

Promptware and LLM-for-SE surveys establish that prompts, agent memory files, and tool interfaces are becoming software engineering objects~\cite{chen2025promptware,hou2024llm4se,fan2023}.
Empirical studies of Copilot and related assistants characterize productivity and interaction rather than corpus construction~\cite{ziegler2024copilot,barke2023groundedcopilot,vaithilingam2022expectation}.
Earlier bot work anticipated automation in developer workflows without treating instruction files as sampling predicates~\cite{storey2020}.
Primary documentation specifies the concrete filenames and configuration surfaces that mining studies can now search for, including \texttt{AGENTS.md}, editor rule paths, Copilot custom instructions, Claude project memory, and the Model Context Protocol~\cite{agentsmd2025,cursor2024docs,brown2024copilot,claude2024docs,anthropic2024mcp}.

This cluster documents the phenomenon that makes instruction-file discovery practically available.
It does not audit whether repositories retrieved via those filenames match the analytic population a study claims, nor does it provide family-level contamination reporting~\cite{chen2025promptware,baltes2022sampling}.
We therefore treat the scarcity of peer-reviewed \emph{sampling} methodology for these predicates as a working observation from the clusters above, not as a measured adoption lag between practice and methodology~\cite{hou2024llm4se,chen2025promptware}.

\subsection{Existing studies using AI instruction artifacts}
\label{subsec:rw-existing-instruction-studies}

Published empirical work that touches agent-instruction ecosystems currently clusters around tool use, adoption, and capability rather than discovery-frame validity.
Copilot studies measure interaction and productivity~\cite{ziegler2024copilot,barke2023groundedcopilot,vaithilingam2022expectation}.
Promptware articulates engineering concerns for prompt-enabled systems~\cite{chen2025promptware}.
Broader LLM4SE surveys map tasks and open problems~\cite{hou2024llm4se,fan2023}.
Companion corpus work on AI convention lifecycle and adoption--maintenance patterns charts how instruction files spread across repositories~\cite{ai_convention_lifecycle_corpus2026}; we cite it only as a related data product, not as a methodological predecessor that already audited sample--target contamination.
Benchmark construction from GitHub issues shows that filtering choices shape evaluation populations, but the inclusion event is issue--patch linkage rather than instruction-file presence~\cite{jimenez2024swebench}.

In the studies above that do engage instruction artifacts as objects, the research estimand is typically assistant use, prompt structure, adoption, or task performance rather than membership of retrieved repositories in a declared analytic population~\cite{ziegler2024copilot,chen2025promptware,ai_convention_lifecycle_corpus2026}.
Consensus-protocol sensitivity of contamination rates is not the reported outcome in that cluster.
Grey documentation of instruction formats is necessary phenomenon evidence~\cite{agentsmd2025,cursor2024docs,brown2024copilot,claude2024docs,anthropic2024mcp}, but documentation is not a methodological audit.
The closest methodological cousins remain general GitHub perils, sampling guidelines, and engineered-project curation, none of which operationalize instruction-predicate family structure or consensus sensitivity for this regime~\cite{kalliamvakou2015indepth,baltes2022sampling,munaiah2017curating,phantom2020}.

\subsection{What remains unsolved}
\label{subsec:rw-unsolved}

Synthesizing the clusters above yields a narrow residual problem.

Already available, at the level of awareness and infrastructure, are GitHub perils~\cite{kalliamvakou2015indepth,howison2004perils}, sampling-frame reporting expectations~\cite{baltes2022sampling}, engineered-project curation for some questions~\cite{munaiah2017curating,phantom2020}, leakage and duplication as distinct contamination senses~\cite{kaufman2012,lopes2017dejavu,allamanis2019duplication,kapoor2023leakage}, label-validation culture in defect and related datasets~\cite{herbold2022szz,shepperd2013nasa,shepperd2014bias}, multi-coder agreement tools~\cite{cohen1960kappa,landis1977kappa}, and artifact or replication norms~\cite{heumuller2020,winter2022artifacts,gonzalez2023revisit,liu2024researchartifacts,silva2012replication}.

Partially available are operational sample--target audits for new discovery predicates, threats-to-validity discourse without worksheets tied to a concrete estimand~\cite{ampatzoglou2019threats,verdecchia2023threats,siegmund2015views}, sensitivity culture for methodological choices in other estimands~\cite{tantithamthavorn2017validation}, and LLM annotation transfer to software engineering membership labels under conflicting evidence~\cite{gilardi2023chatgpt,ahmed2025llms}.

What remains jointly open for AI-instruction discovery frames---on the evidence of the clusters reviewed above---is an integrated account in which:
\begin{enumerate}
  \item contamination is defined as satisfied search predicate and outside the stated analytic population (target-conditional membership error);
  \item misalignment is examined by predicate family rather than only as a frame-wide rate;
  \item complementary consensus protocols are treated as determinants of the contamination estimand on the same labeled repositories;
  \item membership-boundary disagreement is separated from product-role classification in a tiered inspection;
  \item worksheets, frozen labels, and alternative-protocol replay scripts make those checks reportable and repeatable.
\end{enumerate}
Closest neighbors fall short for structural reasons.
Kalliamvakou et al.\ establish perils without instruction-predicate family audits~\cite{kalliamvakou2015indepth}.
Baltes and Ralph provide guidelines without this empirical hinge~\cite{baltes2022sampling}.
RepoReapers and PHANTOM optimize engineeredness, not product-role targets for agent-instruction studies~\cite{munaiah2017curating,phantom2020}.
Leakage and duplication work address a different contamination construct~\cite{kaufman2012,lopes2017dejavu,allamanis2019duplication}.
Promptware and Copilot studies document the artifact ecosystem without mining-frame validity checks~\cite{chen2025promptware,ziegler2024copilot,vaithilingam2022expectation}.
LLM annotation studies address labeling technology rather than discovery-frame contamination rates~\cite{ahmed2025llms,gilardi2023chatgpt}.
Golzadeh et al.\ show how to build membership ground truth for bots, transferring a method pattern but not the instruction-artifact membership construct~\cite{golzadeh2021bots}.

\subsection{Why this article is needed}
\label{subsec:rw-why-needed}

The necessity claim is therefore limited and methodological.
Because instruction-file predicates are now searchable~\cite{agentsmd2025,cursor2024docs,brown2024copilot,claude2024docs,anthropic2024mcp,chen2025promptware}, ordinary perils warnings, engineered filters, and generic sampling guidelines leave an operational gap whenever off-target repositories may still look like engineered software~\cite{kalliamvakou2015indepth,munaiah2017curating,phantom2020,baltes2022sampling}.
Without family-level reporting, heterogeneous predicates risk collapsing into one rate that is hard to interpret~\cite{dabic2021sampling,baltes2022sampling}.
Without consensus-protocol sensitivity, a single operational contamination percentage is easy to over-interpret as protocol-invariant~\cite{tantithamthavorn2017validation,verdecchia2023threats}.
Without replayable worksheets, audits are difficult to compare across targets or to revisit under alternative membership definitions~\cite{heumuller2020,gonzalez2023revisit,winter2022artifacts}.
In short, the literature already tells researchers that GitHub samples can be wrong~\cite{kalliamvakou2015indepth}; it does not yet show how wrongness behaves when the discovery mechanism is an AI-instruction path predicate and the estimand is a multi-coder contamination rate~\cite{baltes2022sampling,tantithamthavorn2017validation,chen2025promptware}.

This article does not propose a new theory of GitHub bias, a replacement for engineered-project curation, or a general sampling methodology~\cite{kalliamvakou2015indepth,munaiah2017curating,baltes2022sampling}.
It also does not treat artifact release or multi-coder worksheets as novel in isolation; those practices are established expectations~\cite{heumuller2020,cohen1960kappa,runeson2009}.
What it contributes is an operational audit for AI-instruction discovery frames---applied to one public GitHub frame---together with reporting recommendations derived from that audit: declare the analytic target, record predicate families, report complementary consensus estimates, and validate labels before scaling claims~\cite{baltes2022sampling,verdecchia2023threats}.
If the audit shows that contamination rates move under alternative consensus protocols while family-level structure remains informative, the scientific payload is a measurement-validity result for a new discovery regime rather than a restatement of GitHub perils~\cite{tantithamthavorn2017validation,kalliamvakou2015indepth,baltes2022sampling}.

Section~\ref{sec:study-design} defines the discover--filter--annotate--inspect pipeline used in the audit; Section~\ref{sec:results} reports protocol sensitivity, family structure, disagreement, and inspection concordance.
